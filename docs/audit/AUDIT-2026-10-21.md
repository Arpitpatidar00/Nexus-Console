# Stackroost — Full App Audit (2026-10-21)

Branch audited: `feat/mac-clean` at `8c3d181` (48 commits, nothing pushed).
Reviewed as five roles: **System Architect**, **Project Manager**, **Lead Tester**, **Lead Product Improver**, **Stakeholders**.

> **How this audit was done.** A static code review of the whole repo with file:line evidence. The test
> suites could NOT be run during the audit (the shell available was Linux; `node_modules` and the Rust
> crates are macOS-only). Every "tests pass" claim below comes from `docs/roadmap/PROGRESS.md` and is
> treated as **unverified**. Phase 0 of the plan re-runs every gate on the Mac and records the real baseline.

## 1. Verdict (for stakeholders)

**The app is real at its core, but the roadmap layer is not.** The original modules (Homebrew, Ports,
Servers core, Doctor, Mac Clean, Claude Chats, Terminal) are solid, well-structured and well tested. The
14 roadmap phases on top were marked "complete" in under 3 hours (01:40 → 04:38, one phase in 7 minutes).
They added ~30,000 lines with ~56 new Rust tests, no new fixtures, and:

- **Command injection** in four places (Backups, Domains, Deploy, Remote files) — including commands that run on **prod servers**.
- A **/etc/hosts editor** that can corrupt the Mac's networking and always reports success.
- **Fake features** shown to the user as working: the chaos proxy never starts, AWS cost always says $0.00, the
  update checker queries a different GitHub repo, the Releases "tracks" are hardcoded labels.
- A **broken AI Explain**: the whole prompt is masked down to 8 characters before Ollama sees it.
- **The safety rules from `CLAUDE.md` / `PRODUCT.md` were not followed** in the new modules: ~45 mutating
  commands have no Rust confirm, `sh -c` strings are used in 7 services, and the frontend uses browser `confirm()`/`alert()`.
- The docs (`README.md`, `FEATURES.md`, `PROGRESS.md`) **describe the fake features as working**.

**Recommendation:** do not ship or demo the roadmap modules until Phase A (safety) and Phase B (truth) of
`docs/audit/PLAN.md` are done. The core app is shippable after the Phase A fixes.

## 5. Lead Product Improver — product findings

1. **Too many modules for a menu-bar app.** 17 modules, several overlapping (Docker vs Servers containers; Doctor vs Mac Clean vs Energy; Backups vs Databases snapshots; Domains uptime vs Servers health). Consolidate into 6 hubs: **Local** (Services, Ports, Docker, Databases), **Servers** (hosts, tunnels, deploy, logs, files), **Projects** (projects, workspaces, secrets, releases), **This Mac** (Doctor + Mac Clean + Energy + Network), **Cloud & Web** (AWS, domains, uptime), **Tools** (Claude Chats, Toolbox, AI).
2. **No "home".** There is no overview answering "is anything wrong right now?" across local, servers, uptime, disk. Add a Home dashboard of real issues only.
3. **Onboarding.** First run lists modules; it does not detect what you actually have (Docker, AWS CLI, Ollama, Flutter) or import your SSH hosts in one flow.
4. **Trust signals.** Each module should show what it reads, what it can change, and what it sends over the network (a small "Privacy & access" line per module).
5. **Daily-use speed.** Global hotkey + palette exist; add pinned actions, recent hosts, and "repeat last action".
6. **Light theme quality** is undermined by hardcoded colours (A-09).
7. **Empty / error states** in new modules are inconsistent (some show nothing when a CLI is missing).
