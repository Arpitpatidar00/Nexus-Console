## 1. Verdict

> **Update, same day:** Fix-1, Fix-2 and Fix-3 (§10) were implemented and committed in `9b3ce87`,
> closing CI-01, ARC-01/TST-01, BUG-01 through BUG-12, SEC-01 through SEC-03 and T-31. The text below is
> left as it was written, as the record of what was found; §10 has the up-to-date status and the few
> sub-items that were explicitly deferred (pty_open's per-target gating, Docker pause/unpause, DB
> discovery on non-default ports). Fix-4 through Fix-6 are still open.

**The core is solid and every automated gate except prettier passes. Several secondary screens fail for
every user, and one database feature can damage data.**

- **5 screens fail on every load** because their zod schemas expect `snake_case` while Rust sends
  `camelCase`: Network (interfaces, bandwidth, chaos), Cloud (EC2, S3, costs) and Backups history. Your
  error log shows these failing repeatedly, as recently as today 02:02. The schema tests pass because they
  parse hand-written snake_case samples instead of real Rust output (ARC-01).
- **APFS database snapshots/restore ignore failures** when stopping Postgres and when moving the data
  directory. A failed stop means a restore swaps the data directory under a running server (BUG-01, S1).
- **CI is red**: `prettier --check .` fails on one lab script that the pre-commit hook does not check (CI-01).
- New since the sign-off and in good shape: Servers (the timeline/note contract errors stopped after
  `dcfa1d5`), the Databases explorer (golden contract test, values never become query text), the Projects
  runner (steps passed as arguments, tested under zsh and bash) and the Storage tools.
- Cross-cutting debt: 118 raw `Command::new` calls with no timeout (ARC-02), ten module commands
  that run with their module switched off (SEC-02), and visible drift from `PRODUCT.md` in older screens (§8).

**Recommendation (at the time this was written):** do Fix-1 (contracts + CI) and Fix-2 (snapshot safety)
before the next release — now done. Fix-4 (hardening), Fix-5 (design language) and Fix-6 (owner decisions
and QA) remain.

## 6. Feature notes (functional checks and code review)

**Homebrew / Packages.** The log shows the error pipeline doing the right thing: `Busy` while brew updates
itself, `UntrustedTap` with a one-click trust, and `conflict` for a busy port. Only the message text is
wrong (BUG-08). `BrewLock` + `ServicesCache` are used everywhere except APFS (BUG-01).

**Servers.** The rework in `dcfa1d5` fixed the timeline and note contracts (last error 10-23 22:21, fix at
23:27), the sticky disconnect, real logs and nginx/cron. 107 Rust tests and 44 frontend tests make it the
best-covered module. Open: the URL paste in the tunnel dialog (BUG-12), the frozen Deploy page, and an
internal ID shown in copy (DES-07).

**Databases.** The explorer is well built: one read-only session per engine; values bound as psql
variables, MySQL hex literals, Mongo EJSON and Redis ARGV, never spliced into query text; a golden contract
(`fixtures/databases/explorer-contracts.json`); exports only to `~/Downloads`, behind the mutation gate. The
risks are at the edges: Mongo credentials on argv (SEC-01), smart quotes (BUG-09), discovery guessing the
data dir (BUG-10), and the snapshot path (BUG-01).

**Docker.** Lab (`scripts/docker-lab`) covers healthy, crashing, paused and compose containers. The local
Docker service is the least hardened code in the app: 6 raw `Command::new`, 1 Rust test, no timeouts,
stderr dropped (BUG-07).

**Mac Clean.** The Projects artifacts and Apps & AI tools reuse `safe_rm`, consent for `~/Library` and the
journal. Separate busy locks and cancel flags avoid the shared-lock collision found while building them.
They are thin on tests (`maclean/projects.rs` 3, `maclean/appdata.rs` 1) and have not been checked visually.

**Projects.** The runner resolves steps in Rust and passes them as positional arguments to a fixed script.
The test `project_steps_run_as_arguments_in_zsh_and_bash` proves a hostile project path cannot run.
"Stop" only signals a pid that is listening with its cwd inside the project, after a confirm. Live:
discovery found 46 projects in 2.6 s. Gaps: `projects/discovery.rs` has no tests since the
`.git` requirement was dropped and depth went to 4; the detail page has not been checked visually.

**Network / Cloud / Backups.** The Rust side is fine (the network info read takes 0.02 s live). The
screens fail only because of the schema drift (BUG-02…06). These three features were written before the
camelCase rule, and their tests copied the wrong shape.

**Secrets.** `.env.example` and other templates are now classified (`env_file_kind`, `looks_like_placeholder`)
with tests. Test-context hits remain (BUG-13).

**Blueprint / AI / Settings.** Blueprint apply runs outside the module gate (SEC-02), and its import is
cast instead of validated (BUG-11). Settings → Privacy is complete except for database hosts (SEC-03).

## 7. Architecture and design patterns

**What is good (keep it):** the IPC spine (`ipc()` + zod + `CMD`, every command registered); validated
newtypes; the mutation gate with native confirms and the journal; `core::store` (atomic, versioned,
corrupt-file quarantine); consent enforced in Rust; one scheduler thread; the redacted diagnostics log. The
newer modules (Servers rework, Databases explorer, Projects runner) follow all of these. Checked and fine:
the 8 sync commands are all trivial (no shell-out); no persisted state bypasses `core::store`. The other
non-test `fs::write` calls are exports with server-composed paths (Doctor report, DB export to
`~/Downloads`, Claude archive), the hosts backup, and a temp Brewfile.
